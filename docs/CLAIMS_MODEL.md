# Claims model: deconstructing the scholarship into claims, warrants, open questions and importance

Status: v1, 2026-09-26. Answers P20260926041129 (claims, warrants, open questions, importance scores, a system that
corrects itself) and P20260926041711 (relevance of every card to Pico's relationships). Extends
`docs/DATA_ONTOLOGY.md` and `docs/RESEARCH_PROTOCOL.md` (thesis-keyed mentions and claims, built in another window);
it does not replace them. Inherits `docs/ORCHESTRATION.md` (roles, gates, one writer per file) and
`docs/EDITORIAL_STANDARD.md`.

## 1. Why a claims layer

The audit (`audit/A3`) found that a commentary was written from an LLM's memory of scholars: quotations that are not in
the books, debates between scholars who never met, page numbers that were Markdown line numbers. The cure is to make
the **claim** the unit of scholarship. Nothing reaches prose, a card or a score except through a claim that a script has
checked against the page. A claim says what a scholar or Pico says, on whose authority, on what evidence, and what the
source itself leaves open.

| term | meaning here |
|---|---|
| **claim** | one thing a source asserts, restated in a sentence, tied to one or more verbatim quotations |
| **warrant** | what the source offers in support of the claim (a text of Pico, other scholarship, an argument, an authority, or an inference) |
| **open question** | what remains unsettled about the claim, as the source itself says or as the evidence shows |
| **hedge** | the source's own epistemic stance: assertive, hedged, speculative, evidenced by the source's words |
| **link** | a relation between two claims, usually across scholars: supports, contradicts, qualifies, depends on, same claim |
| **bears_on** | which of Pico's relationships (Ficino, Poliziano, the commission ...) the claim illuminates, and how |
| **importance** | a computed triage score for editorial attention (section 5). It is not a truth value |

## 2. Reconciliation with `DATA_ONTOLOGY.md`

| ontology field | this model |
|---|---|
| `Claim.text`, `claim_type`, `entities` | same names and enum (`claim_type` adds `textual_crux`, `method`, `reception`) |
| `Claim.source {scholar, work, locator}` | `claimant`, and `quotes[] {text, work, line}`; the locator is *verified*, not asserted |
| `Claim.counterarguments`, `supporting_evidence` | `relations_local` (within a packet) and `links` (across packets) |
| `Mention.confidence` (`verbatim_quotation` / `paraphrase` / `inferred`) | the quote gate: `verbatim` / `verbatim_modulo_marks` / `altered` / `not_found`; a paraphrase without a quotation is not a claim |
| `Thesis.historiographical_importance` | computed here for claims, topics and theses (section 5) |
| new | `warrants`, `open_questions`, `hedge`, `bears_on`, `judged.frame_shift`, `attribution` |

Thesis-keyed claims carry `theses: ["2>10", ...]` (Farmer ids). Angelology claims are keyed by `topics` and `pico_locus`
because most of Pico's angelology is not in the 900.

## 4. The packet (what a RESEARCHER writes)

```json
{ "packet": "black2006-a", "researcher": "R-BLACK-A", "created": "2026-09-26",
  "scope": {"work": "black2006", "line_start": 1, "line_end": 4700},
  "claims": [ CLAIM, ... ],
  "not_mined": ["passages in scope not extracted, and why"],
  "proposed_topics": [{"id": "...", "label": "..."}], "proposed_parties": [{"id": "...", "name": "..."}],
  "notes": "cruxes, OCR problems, anything the next agent needs" }
```

```json
CLAIM = {
  "id": "black2006-a:001",              // "<packet>:<nnn>"; never reused
  "claimant": "Crofton Black",           // who makes the claim: the scholar, or "Pico" for his own text
  "attribution": "scholar_claim",        // scholar_claim | scholar_report (reports another's view) | primary_text (Pico's own words)
  "claim_type": "interpretive_position", // doctrinal_content | source_identification | interpretive_position | historical_event | textual_crux | method | reception
  "topics": ["three-worlds"],            // ids from data/claims/topics.json
  "pico_locus": {"text": "heptaplus", "ref": "second proem"},   // where in Pico's work this bears; null if none
  "theses": [],                          // Farmer ids, if the claim concerns particular theses
  "text": "One neutral sentence restating the claim. A paraphrase, never a quotation.",
  "quotes": [ {"text": "verbatim from the source", "work": "black2006", "line": 8408, "page": null, "page_basis": null} ],
  "hedge": "assertive",                  // assertive | hedged | speculative
  "hedge_words": "",                     // required unless assertive: the source's own hedging words, present in a quote
  "entities": ["Anaxagoras"],            // people, works, places the claim names; each must occur in a quote
  "warrants": [ {"id": "w1", "kind": "primary_text", "text": "how it is supported", "quote": {"text": "...", "work": "wallis1965", "line": 3930}} ],
  "assumptions": ["what the claim takes for granted"],
  "open_questions": [ {"id": "q1", "kind": "evidence_gap", "text": "what is unsettled", "basis_quote": null} ],
  "relations_local": [ {"to": "black2006-a:004", "relation": "depends_on", "basis": "why"} ],
  "bears_on": [ {"party": "ficino", "kind": "quarrel", "note": "how it bears on the relationship", "quote_index": 0} ],
  "judged": {"frame_shift": 0, "justification": ""}   // 0-3: does it change how a Pico passage is read? JUDGED, and labelled so
}
```

Rules for the packet (each catches a failure the audit found):

1. **Quotations are copied from the file, never from memory.** Use `python scripts/corpus_tool.py check WORK LINE "quote"`
   before you write one. Quote what the claim needs (4 to 120 words); use `...` for omissions and `[...]` for your
   insertions. The verifier reduces text to letters and digits, so OCR spacing and hyphens do not matter, but a changed
   word does.
2. **`text` must not outrun its quotations.** Every name, date and number in `text` and `entities` must occur in a quote.
   A claim about what a scholar *infers* says "infers"; a claim the scholar hedges is `hedged` with the scholar's words.
3. **Keep three voices apart.** `attribution` says whether the quotation is the scholar's own claim, the scholar reporting
   another's view (then `claimant` is the reporter, and the reported author is named in `text`), or Pico's own text from an
   edition (`wallis1965`, `borghesi2012`, `farmer1998`, ...). A scholar's claim cannot be evidenced from Pico's text alone.
4. **A warrant of kind `primary_text` or `scholar_evidence` carries the quotation that is the evidence.** An `inference`
   warrant lists its `basis`. If the source gives no warrant, write none; the score will show the claim is bare.
5. **Record open questions only where the source or the evidence leaves the matter open.** Cite the source's own words
   when it says so (`basis_quote`).
6. **`frame_shift` is a judgement.** 0 restates what is standard; 1 refines; 2 changes how a passage is read; 3 overturns
   a received reading. Justify anything above 0 in one sentence.
7. **Pages.** Give `page` only when a printed page marker in the OCR supports it, and say which (`page_basis`, e.g.
   "bracket [199] at l. 10224 opens the next page"). Otherwise cite the line. Never put a Markdown line in `page`.
8. **Do not resolve contradictions between sources.** Write both claims and link them.
9. **Cover the scope.** Read the whole range, not the parts that look promising; list what you skipped in `not_mined`.
10. **One writer per file.** Write only your packet. Never edit another packet, `links`, `scores`, `parties` or `topics`.

## 5. Scoring: historiographical importance

`scripts/claims_score.py` computes the following for every *verified* claim (unverified claims score 0 and are listed).
Weights and cut-offs are in `data/claims/scoring.json`; changing them is a decision recorded in `DECISIONS.md`.

| metric | definition | kind |
|---|---|---|
| `corroboration` | distinct claimants among the claim and the claims linked to it as `same_claim` or `supports` | computed |
| `centrality` | number of other verified claims that link to it (any relation): how much the rest of the argument leans on it | computed |
| `contestation` | 1 if another claimant's verified claim `contradicts` it, 0.5 if one `qualifies` it, else 0 | computed |
| `warrant_strength` | mean warrant weight: primary_text 1.0, scholar_evidence 0.7, argument 0.5, authority 0.4, inference 0.3; no warrant 0.2; a `primary_text` claim is 1.0 | computed |
| `reach` | breadth: topics plus relationship parties touched, capped | computed |
| `frame_shift` | the researcher's 0-3 judgement, scaled | **judged** |
| `open_question_load` | number of open questions (reported, not part of importance: it measures research value) | computed |

`importance = 100 * sum(weight_i * normalised metric_i)`. Tiers by rank: **primary** (top 15%), **secondary** (next 35%),
**tertiary**. The same metrics aggregate to topics and to Pico loci (mean of the top three claims, plus claim count).
An importance score decides where an editor reads first and how much space a card gives a claim. It never decides
whether something is true, and a card must show the components, not only the total.

## 6. The self-correcting loop

```
RESEARCHER writes packet
   -> claims_verify.py opens every source: grades each quotation, warrant and locator; writes verdicts + tickets
   -> tickets carry the nearest real text from the source (`suggested_excerpt`) and the true line
RESEARCHER (or a fixer) applies the tickets; `--fix-locators` repairs wrong line numbers mechanically
   -> claims_verify.py again ... until no claim needs a fix
semantic VERIFIER (a different agent) reads `<packet>.sample.md`: does `text` overreach its quotations?
   -> overreaching claims become tickets of kind `overreach`
LINKER links claims across packets (each link states its basis)
   -> claims_score.py verifies the links, scores, writes relevance and open questions
WRITER composes only from verified claims -> commentary_check.py refuses dangling, unverified or unquoted citations
```

Failure is information: every ticket type maps to a rule in section 4, and a recurring ticket type is a reason to change
the researcher brief, not to relax the gate. The verifier checks that the words are there; it cannot check that the
restatement is fair. That gap is why the semantic sample exists and why "verified" on a claim means *quotation
located and restatement sampled*, not *true*.

## 7. Relevance to Pico's relationships

Every card (a thesis, a claim, a topic, a passage of Pico) gets a relevance score for each **party** in
`data/claims/parties.json`: Ficino first, but equally Poliziano, Savonarola, Lorenzo, Barbaro, the commission,
Cittadini, anyone with whom Pico corresponded or quarrelled (P20260926041711, and the clarification typed at
04:1x UTC: "it could be with anyone he corresponded or quarrelled with").

`relevance(card, party) = normalised sum over verified claims c attached to the card and bearing on the party of
kind_weight(kind of c.bears_on) * importance(c)`, scaled 0-1 per party, with the evidence list of claim ids. `kind_weight`:
quarrel 1.0, trial 1.0, correspondence 0.8, source 0.8, teaching 0.7, patronage 0.7, friendship 0.6, reception 0.5, other 0.4.
A card's relevance is therefore *earned by evidence*: no verified claim linking it to the party, no score, and the
card shows "no evidence yet" rather than zero. Theses reach the matrix through claims that name them (`theses`) and,
for the whole 900, through person connections built from the mention harvest (`data/ontology/`); that ingestion is
ticket T-REL-02. The card displays the score as a bar with its party colour, and a click opens the evidence.

## 8. Relation to the intellectual network system

A parallel design (`docs/INTELLECTUAL_NETWORK_DESIGN.md`, `docs/NETWORK_SYSTEM_HANDOVER.md`) models Pico's persons,
typed directed relationships, relationship evidence, text-to-person relevance and eight scoring dimensions under
`data/network/`. The two systems meet at the claim:

- **A verified claim is a unit of relationship evidence.** `bears_on` says which relationship a claim illuminates; the
  network's `RELATIONSHIP_EVIDENCE` rows are built from verified claims (same quotation gate), never from unverified text.
- **Person ids.** `data/claims/parties.json` is a seed. When `data/network/persons.json` exists, its ids replace the
  slugs and `network_bootstrap.py --source parties.json --merge` carries these over. Until then a packet's `bears_on.party`
  is a proposal, and `claims_score.py` reports slugs that are not in `parties.json` as `unknown_parties`.
- **Evidence level.** `claims_score.py` gives each claim an `evidence_level` on the network's 5-0 scale: 5 Pico's own
  verified words; 4 a scholar's claim warranted by Pico's text; 3 warranted by other scholarship; 2 asserted without a
  stated warrant; 1 hedged as speculative by the source (a plain hedge caps at 2). Level 0 (unsupported) cannot occur:
  an unverified claim is excluded.
- **Relationship kinds** (`bears_on.kind`) map to the network's controlled vocabulary as follows; the integration layer
  applies the mapping, a researcher never needs the finer term:

| `bears_on.kind` | network `relationship_type` |
|---|---|
| quarrel | philosophical_disagreement, polemical_opponent, theological_opponent (choose by the quotation) |
| correspondence | correspondence |
| friendship | friendship, intellectual_circle |
| patronage | patronage |
| teaching | teacher, student, collaborator, translator |
| source | source, studied_work, cited_work, work_known_indirectly |
| reception | reception_figure, posthumous_editor |
| trial | trial_participant, institutional_relationship |
| other | acquaintance, intermediary, intellectual_influence, philosophical_interlocutor |

- **Scores.** The network's eight dimensions (textual centrality, source relation, network relevance, controversy,
  historical significance, evidence quality, tradition significance, reception) are its own scoring pass over
  `text_person_relationships.json`. This model supplies three of its inputs from verified evidence: `evidence_quality`
  (from `evidence_level`), `controversy` (from `contestation` and `quarrel` claims) and `historical_significance`
  (from `trial` claims), plus the claim-level `importance` that decides how much a card shows. The relevance matrix of
  section 7 is the claims-based input; the network's is authoritative once it exists, and the site must read one of the
  two, never both (ticket T-REL-03).

## 9. What this does not do

- It does not read a scholar for the reader; it extracts claims a scholar makes.
- Restatements are paraphrases by a model. They are labelled as such on every card and sampled by a second agent, but
  a claim is only as good as its quotation. Cards must show the quotation.
- Importance and relevance are triage instruments with published weights, not measures of truth.
- Pico's Commento is not in the corpus (Allen's essay quotes Jayne's translation and Garin's edition): claims about it
  are claims *about* it, attributed to Allen, and never "Pico says".
